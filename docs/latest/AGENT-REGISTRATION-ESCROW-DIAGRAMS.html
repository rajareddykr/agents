3. The three secrets — separation of duties#

Read it as: the credential opens the door, the passphrase opens the box. Neither one alone yields a private key — which is why a total control-plane compromise yields ciphertext.

4. Restart-survival states (what an operator sees)#

epoch_count is what separates Awaiting first start from NEW DID on restart. Both report credential yes / key no — and they mean opposite things. Without it the UI warned on every fresh registration, which teaches operators to ignore the warning that matters.

5. Fail-open vs fail-closed#

The asymmetry is deliberate, and it is the rule to remember: reads fail closed, writes fail open.

6. Lifecycle — rotate, revoke, re-register#

7. Why the identity key must never rotate#

Escrowing a rotated key is strictly worse than storing nothing: refusing leaves the previous blob current, still matching the DID, so the agent restarts as itself.

8. Where this sits in the stack#

The agent side borrows the crypto from agent-mesh but does its own transport. One consequence for deployment order: the SDK release depends on the agent-mesh change shipping first — without it, escrow silently degrades and every restart mints a new DID while the test suite goes green by skipping.
